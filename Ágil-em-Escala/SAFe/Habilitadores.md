Dentro do contexto do Scaled Agile Framework (SAFe), um "Habilitador" ou "Enabler" refere-se a itens de trabalho que apoiam as atividades do programa e ajudam as equipes a entregar valor. Eles podem ser necessários para desenvolver arquitetura, explorar novas soluções, facilitar a integração entre equipes e componentes, ou endereçar outros aspectos não funcionais.

Os "Habilitadores" referem-se a itens de trabalho que são necessários para apoiar a construção e entrega de soluções, mas não são funcionalidades visíveis para o usuário final. Eles podem ser necessários para desenvolver arquitetura, resolver impedimentos técnicos, garantir integração ou abordar outros aspectos técnicos.

Os habilitadores podem se manifestar em diferentes níveis do SAFe:

1. **Habilitadores de História de Equipe (Team Enabler Stories)**: Essas histórias ajudam as equipes a desenvolver, refinar ou melhorar a infraestrutura, arquitetura ou outros aspectos técnicos. Por exemplo, configurar um novo servidor de integração contínua pode ser uma história habilitadora para uma equipe.

2. **Habilitadores de Recurso (Feature Enablers)**: No nível de Programa, onde recursos são coordenados entre várias equipes, os habilitadores de recurso podem ser necessários para preparar a arquitetura ou infraestrutura para suportar futuros recursos planejados.

3. **Habilitadores de Capacidade (Capability Enablers)**: No nível de Solução, onde capacidades são definidas e desenvolvidas com a ajuda de várias ARTs (Agile Release Trains), os habilitadores de capacidade apoiam aspectos técnicos ou de infraestrutura em uma escala maior.

4. **Habilitadores de Portfólio (Portfolio Enablers)**: No nível mais alto do SAFe, os habilitadores de portfólio podem ser iniciativas ou épicos que ajudam a criar, melhorar ou mudar processos, sistemas ou ferramentas necessários para as atividades de portfólio.

Independentemente de onde se manifestam, os habilitadores:

- **São Essenciais**: Embora possam não entregar valor direto ao usuário final da mesma forma que uma característica ou capacidade, os habilitadores são essenciais para a construção de soluções sustentáveis e de alta qualidade.

- **São Temporários**: Eles existem para apoiar a criação de valor e, uma vez que o trabalho necessário é concluído, o habilitador é considerado "feito".

- **Têm Critérios de Aceitação**: Como todos os itens de trabalho, os habilitadores têm critérios de aceitação que definem claramente quando são considerados completos.

O conceito de habilitador no SAFe ajuda as organizações a reconhecer e planejar o trabalho necessário que apoia e facilita a entrega de valor, garantindo que as considerações técnicas e de infraestrutura não sejam negligenciadas.

# Sobre Epics & Enablers

## Epic

Um epic é uma iniciativa significativa de desenvolvimento de soluções, os épicos são responsável por grande parte dos investimentos das organizações e também pelo custo de investimento para novas soluções.

Os épicos normalmente precisam ser aprovados e priorizados pelo LPM, o custo atrelado a épicos é alto e precisa estar em conformidade com a gestão do portfólio.

A organização possui diversos épicos compartilhamos com diversos fluxos de valor. O framework SAFe sugere que os épicos sejam desenvolvidos com uma forma Lean, utilizando conceitos de Lean Startup com MVPs.

## Enablers

Um enabler suporta as atividades necessárias para habilitar uma pista de arquitetura que suporte às funcionalidades solicitadas pelo negócio. Normalmente compostos por itens de infraestrutura, arquitetura e conformidade. Fazem parte da maioria dos backlogs.

Como dito anteriormente, os enablers ou traduzindo para o português habilitadores, não só construam uma pista para arquitetura atual mas olham para os requisitos do negócio.

Em nosso dia a dia os enablers “competem” com a priorização das features dos mais diversos negócios. É muito importante saber como demonstrar o valor de todo esse suporte ao desenvolvimento/negócio.
